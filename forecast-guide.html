1. The question we ask

Every model answers the same question: given someone's history, what will their best lift be on a future date? Instead of predicting kilograms directly, it predicts the percentage change from the last best. A 5% gain means the same thing for a 60 kg bench as a 200 kg deadlift, so one model can learn from everybody.

To make percentages add up neatly, we use the natural log of the ratio. Statisticians call this the log return:

y=ln⁡(next bestlast best)and back again:forecast kg=last best×ey^

Example: squat goes 120 → 126 kg. y = ln(126/120) = ln(1.05) ≈ 0.049. If a model predicts ŷ = 0.049 for someone at 120 kg, the forecast is 120 × e0.049 ≈ 126 kg. For small changes, y is roughly the percentage (0.049 ≈ 5%).

2. Turning results into lessons

The data is OpenPowerlifting, a public-domain record of 4.05 million meet results from 1.0 million lifters. We kept raw (no supportive suits) lifting only, because that matches gym training. Each lifter's results, in date order, become a chain of lessons. Each lesson has the shape "here's what we knew before, here's what happened next."

After cleaning, that gave 2,184,085 examples from 270,686 lifters, across squat, bench and deadlift. The typical gap between results is 171 days. Cleaning dropped obvious errors, such as two different people with the same name (a lift jumping more than 60%, or bodyweight changing more than 35%).

02_features.py

# sort each lifter's results by date, then look one step back
g = d.groupby(["lift", "Name"], sort=False)

d["y"] = np.log(d.kg / d.prev_kg)       # the target: log change

4. Testing it fairly

A model that has seen the answers can look brilliant and still be useless. So we split by date, the way real forecasting works. Models learn from the past, and we grade them only on the future.

5. The models, one by one

We tried six approaches, from simple to complex. They're arranged so each one shows what the next adds.

Baseline: "same as last time"

The forecast is your last best, unchanged (ŷ = 0). It sounds silly, but any model that can't beat it is worthless. It misses by 9.1 kg on average.

Lookup table

Put everyone into buckets by lift, sex, experience, gap and strength level, then predict each bucket's median gain. It's like a chart in a training book. It misses by 8.0 kg.

tbl = train.assign(b=buckets(train)).groupby("b").y.median()
pred = buckets(test).map(tbl).fillna(overall_median)

Ridge regression with splines

A weighted sum of the inputs. Each feature gets a weight w, and the model picks the weights that make the squared errors smallest. Ridge adds a penalty that keeps the weights small so they don't chase noise. Splines let a feature bend, so "gains slow down with experience" can curve instead of being a straight line.

y^=b+∑jwjxjchoose w to minimise ∑i(yi−y^i)2+α∑jwj2

α = 10 here. It misses by 7.5 kg. It's limited because it can't easily learn that two things together, like "beginner and gaining weight", matter more than each alone.

LightGBM: gradient-boosted decision trees

A decision tree asks yes/no questions until it reaches an answer. This is the real top of the first tree LightGBM built:

One tree is crude. Boosting builds trees one after another. Each new tree is trained on the mistakes (residuals) the trees before it are still making, and adds a small correction:

Fm(x)=Fm−1(x)+η·treem(x)treem fits y−Fm−1(x)

η = 0.05 is the learning rate: each tree fixes only 5% of what it sees, so no single tree can overreact. It stopped at 491 trees, when the late-2022 "Stop" data stopped improving. It misses by 7.13 kg.

LightGBM with Huber loss

The same thing with a different way of scoring mistakes. Squared error lets one bad record (a typo, a bombed-out meet) dominate. Huber loss is squared for small errors and straight-line for big ones, so outliers count less:

L(r)={12r2if |r|≤δδ(|r|−12δ)otherwiseδ=0.08 (about 8%)

This was the best single model: 7.07 kg average miss, using 822 trees.

XGBoost

Another boosting library. LightGBM grows each tree by splitting the single most useful leaf next. XGBoost grows level by level, here up to 8 levels deep. Different tree shapes make different mistakes, which helps the stack later. It stopped at 549 trees and misses by 7.13 kg.

Neural network

A multilayer perceptron with three layers of 128, 64 and 32 "neurons". Each neuron takes a weighted sum of the layer before it and passes it through ReLU, which just means "keep it if positive, else zero". Layer by layer, it builds its own combinations of the features.

h1=max(0,W1x+b1),h2=max(0,W2h1+b2),…,y^=wout·h3+bout

Trained with the Adam optimizer on a 600,000-row sample, stopping when it no longer improved. It misses by 7.20 kg. That's slightly behind the trees, which is typical for table-shaped data like this.

6. Stacking them together

Each model gets things wrong in slightly different ways, so averaging them can cancel some errors out. Stacking learns the best mix. We take every model's predictions on the 2023 "Blend" data, which none of them trained on, and find non-negative weights that best match what really happened:

y^stack=∑kwky^kwk≥0,fit by non-negative least squares

We also tried a second stacker, a small LightGBM that sees all the models' predictions plus the gap and experience. It didn't do better (7.08 kg).

The truthful result: stacking had the best RMSE (10.34 kg) and R², but it beat the best single model by about 0.01 kg. The boosted trees had already found nearly all the signal in these features. More complex models stop helping when the remaining error is mostly day-to-day randomness: sleep, nerves, a missed lift.

7. The likely range

A single number hides how uncertain the future is, so two extra LightGBM models predict the 10th and 90th percentiles instead of the middle. They use quantile (pinball) loss, which punishes being on one side more than the other:

Lτ(r)={τ·rr≥0(τ−1)·rr<0τ=0.1 for the low edge, 0.9 for the high edge

The check: if the range is honest, real results should fall inside it 80% of the time. On the 2024–2026 final exam they did 80.1% of the time (81.1% for the phone model).

How to read the columns:

  • Avg miss (mean absolute error) is the typical gap between forecast and reality. For someone squatting 150 kg, 7 kg is about one small-plate jump either way.
  • RMSE squares the misses before averaging, so the occasional big miss counts more. It's higher than the average miss because some results are surprises.
  • R² = 0.31 means the model explains about 31% of the variation in how much people gain. The rest is randomness no model can see from a training log.
  • Up/down right is how often the model correctly called whether the lift would rise or fall.
What it means for you. The model learned from competitors' meet-day maxes. Your app numbers are estimated 1RMs from gym sets, so expect it to be a little cautious for beginners and the range to be a little narrow. It knows squat, bench and deadlift only. As your own log grows, your history features carry more weight, so forecasts get more personal over time.

9. Running it on your phone

The full stack is too heavy for an offline phone app, so the app uses one compact LightGBM: 600 trees for the middle forecast, plus 300 each for the low and high edges. That's about 330 KB, and it misses by 7.14 kg, only 0.07 kg behind the full stack. Python exports the trees as plain lists of numbers, and about 20 lines of JavaScript walk them:

forecast.js

function treePredict(tree, x) {
  let n = 0;
  for (;;) {
    const goLeft = x[tree.f[n]] <= tree.t[n];       // "is feature f at most threshold t?"
    const c = goLeft ? tree.l[n] : tree.r[n];
    if (c < 0) return tree.v[~c];                  // reached a leaf: its small adjustment
    n = c;
  }
}
// (simplified: the real file also handles missing values)
// forecast = last best × e^(sum of every tree's adjustment)
const y = model.trees.reduce((s, t) => s + treePredict(t, x), 0);
const forecastKg = lastBest * Math.exp(y);

I checked that the JavaScript gives the same answers as Python on 2,000 test cases, to within 0.00002. To draw the chart, the app runs this every two weeks into the future, with your bodyweight plan filled in for each date. The first 8 weeks are eased in from today's value, and the line is never allowed to go backwards.
